# การตั้งค่าระบบตรวจจับหลังอัปเดต

> **อัปเดตล่าสุด — ต้องสแกนสินค้าทุกชิ้นใหม่หนึ่งครั้ง**
> ระบบตัดพื้นหลัง/แท่นหมุนออกจากภาพก่อนสร้าง embedding แล้ว (`EMBED_VERSION = 2`)
> ทั้งตอนเพิ่มสินค้าและตอนจดจำ ทำให้ผลเทียบกันได้ต้องมาจากวิธีเดียวกัน
> สินค้าที่เพิ่มไว้ก่อนหน้าจะขึ้นป้าย **"ต้องสแกนใหม่"** ในหน้าจัดการ/เพิ่มสินค้า
> และจะยังจดจำไม่ได้จนกว่าจะกดแก้ไข/ลบแล้วสแกนใหม่ (ข้อมูลชื่อ ราคา เรื่องราว ไม่หาย)
> การเพิ่มสินค้าตอนนี้ต้องมีภาพพื้นเปล่าของกล้องนั้นก่อนเสมอ

1. เปิด `http://127.0.0.1:8000/calibrate` เลือกกล้องที่ใช้จริง
2. เอาสินค้าและมือออกจากแท่น รอภาพนิ่ง แล้วกด **บันทึกภาพพื้นเปล่า**
   รุ่นนี้เก็บพื้นอ้างอิงแยกตามหมายเลขกล้อง ไม่ใช้ไฟล์พื้นเก่าที่ไม่ทราบกล้องต้นทาง
   และไม่จำภาพแรกเป็นพื้นว่างอัตโนมัติ
3. ตั้งกรอบให้รวมสินค้าทั้งชิ้นในทุกมุมหมุน แต่ลดโต๊ะและสิ่งของรอบข้างให้น้อยที่สุด
   เว้นพื้นหลังนอกกรอบไว้บ้าง เพื่อชดเชยความสว่างจากพื้นที่ที่ไม่มีสินค้า
4. ดูค่าขณะว่างและขณะวางสินค้าชิ้นเล็กที่สุด ตั้ง `off` สูงกว่าค่าว่างเล็กน้อย
   และ `on` ต่ำกว่าค่าที่มีสินค้า โดย `on` ต้องสูงกว่า `off` เสมอ
5. เก็บภาพสินค้าในแสงและมุมกล้องที่ใช้จริง ให้เห็นหลายด้าน ไม่มีมือบัง
   เลือกอย่างน้อย 3 ภาพ แนะนำ 5 ภาพขึ้นไปที่แตกต่างกันและชัดเจน
   หากเปลี่ยนกรอบหรือมุมกล้องมาก ต้องถ่ายตัวอย่างสินค้าใหม่ให้ตรงกัน
6. ทดสอบวาง/ยกออกหลายรอบ รวมสินค้าหน้าตาคล้ายกัน และของที่ไม่ได้ลงทะเบียน
   หลังเลือกสินค้าด้วยตนเอง ให้ยกออกก่อนเปลี่ยนชิ้นใหม่

หน้าเพิ่มสินค้าใช้ปุ่ม **สแกนสินค้าเพื่อเพิ่มเข้ารายการ** เก็บภาพจากกล้องโดยตรง
จึงเพิ่มสินค้าได้แม้ยังไม่ได้ตั้งพื้นอ้างอิงสำหรับการตรวจจับอัตโนมัติ
วางสินค้าชิ้นเดิมไว้ตลอดการเก็บภาพ เลือกภาพ กรอกข้อมูล แล้วกดบันทึกเข้ารายการ
สินค้าใหม่จะปรากฏในรายการด้านล่าง โดยใช้ฐานข้อมูลเดียวกับหน้าจัดการสินค้าเดิม
การใช้งานหน้าจอสแกนอัตโนมัติยังต้องตั้งพื้นเปล่าตามขั้นตอนด้านบน

## สิ่งที่แก้

- ใช้คะแนนมัธยฐานร่วมกับค่าเฉลี่ยที่ตัดค่าปลายของภาพหลายมุม แทนคะแนนสูงสุดของภาพเดียว
- การยืนยันอัตโนมัติต้องมีอย่างน้อย 5 ภาพ โดยอย่างน้อย 70% เลือกสินค้าตัวเดียวกัน
  และอย่างน้อย 65% ผ่านเกณฑ์ความคล้าย ค่าคู่แข่งใกล้กันจะให้ผู้ใช้เลือก
- กรองภาพเบลอ มืด/สว่างจนรายละเอียดหาย และพักเก็บภาพเมื่อการเคลื่อนไหวสูง
- ไม่ใช้ภาพเก่าเกิน 1.5 วินาทีหรือเก็บเฟรมเดิมซ้ำเมื่อกล้องค้าง
- ยกเลิกผลเมื่อยกสินค้าออก เปลี่ยนกล้อง กรอบ หรือฐานภาพสินค้าระหว่างสแกน
- ตรวจซ้ำด้วย 3 ภาพและต้องผิดจากสินค้าเดิม 2 รอบ ก่อนเก็บชุดใหม่
  ถ้ายังเป็นสินค้าเดิม จะไม่บันทึกยอดสแกนซ้ำและไม่เริ่มวิดีโอใหม่
- รอให้กล้องปรับตัวหลังเปิด เชื่อมต่อใหม่กับกล้องเดิมเมื่ออ่านภาพไม่ได้
  ไม่สลับไปกล้องอื่นเงียบ ๆ และไม่ปรับพื้นอ้างอิงเองจนกลืนสินค้า
- ตรวจข้อมูลกรอบและ threshold ป้องกันค่าที่ทำให้กล้องหยุดทำงาน
- บันทึกสินค้าและ embeddings ใน transaction เดียว ปฏิเสธรหัสภาพซ้ำที่ใช้หลอกจำนวนขั้นต่ำ
- อัปเดตจอเมื่อสินค้าต่างกันแม้สถานะยังเป็น `matched` เหมือนเดิม
  เก็บผลที่ผู้ใช้ยืนยันไว้จริง และแสดงคะแนนเป็นความคล้าย ไม่ใช่อัตราความถูกต้อง
- ใช้โมเดลและวิธีสร้าง embedding เดิม จึงไม่ต้องแปลงข้อมูลสินค้าเก่า
  การคำนวณหลายภาพพร้อมกันผ่านการเทียบกับวิธีเดิมแล้ว

## ตัดพื้นหลังก่อน embed (รอบล่าสุด — ต้องสแกนสินค้าเดิมใหม่)

- ก่อนสร้าง embedding ทุกเฟรม ระบบเทียบกับภาพพื้นเปล่าที่ตั้งไว้ (ตัวเดียวกับที่ใช้ตรวจจับ)
  เพื่อแยกตัวสินค้าออกจากแท่นหมุน/โต๊ะ/ของรอบข้าง แล้วเบลอส่วนพื้นหลังทิ้ง —
  embedding จึงอธิบาย "สินค้า" ไม่ใช่ "บูธ" ซึ่งเป็นจุดที่ CNN ทั่วไปมักสับสน
  ทำเหมือนกันเป๊ะทั้งตอนเพิ่มสินค้าและตอนจดจำ (`camera.build_masked_crop`)
- ถ้าไม่มีภาพพื้นเปล่า หรือแยกตัวสินค้าไม่ได้ จะใช้ภาพครอปปกติแทน (เงื่อนไขเดียวกันสองฝั่ง)
- `product_embeddings` มีคอลัมน์ `version` การจับคู่ใช้เฉพาะ `EMBED_VERSION` ปัจจุบัน
  ของเวอร์ชันเก่าไม่ถูกนำมาเทียบและสินค้านั้นถูกทำเครื่องหมายให้สแกนใหม่
- มิติเวกเตอร์และโมเดลไม่เปลี่ยน จึงไม่ต้องแปลงไฟล์ฐานข้อมูล

## ปรับเพิ่มความนิ่ง (รอบก่อนหน้า — ไม่ต้องสแกนสินค้าเดิมใหม่)

- **ยืนยันก่อนสลับจอ:** เมื่อจอแสดงสินค้าอยู่แล้ว การสแกนที่ได้ผลต่างออกไป
  (สินค้าคนละชิ้น หรือกลายเป็น unknown/ambiguous) ต้องเกิดซ้ำ 2 ครั้งติดกัน
  ก่อนจอจะเปลี่ยน — เฟรมสั่นชุดเดียวจึงสลับจอไม่ได้ การจับครั้งแรกจากสถานะว่างยังทันที
- ดีบาวซ์การมี/ไม่มีสินค้าแน่นขึ้น (`PRESENCE_ON/OFF_FRAMES`, `*_HOLD_S`) เพื่อกันมือที่ยื่นเข้ามา
  เงาที่พาดผ่าน หรือเฟรมรบกวนเดี่ยว ๆ ไม่ให้พลิกสถานะ (ซึ่งจะรีเซ็ตการจดจำ)
- เก็บภาพชุดนานขึ้น (`BURST_DURATION_S` 7→9 วินาที) ให้ครอบคลุมมากกว่าหนึ่งรอบหมุน
  ได้มุมที่ต่างกันมากขึ้นต่อการสแกนหนึ่งครั้ง
- ยืดเวลา/จำนวนครั้งของการตรวจซ้ำ (`REVERIFY_INTERVAL_S`, `REVERIFY_FAILURES` 2→3)
  และเพิ่มจำนวน retry ต่อการวางหนึ่งครั้ง (`SCAN_MAX_RETRIES` 2→3)
- ทนกล้องสะดุดสั้น ๆ ได้ (`FRAME_MAX_AGE_S` 1.5→2.0) โดยไม่ล้างผลที่แสดงอยู่
- ค่าความคล้าย/มาร์จิน (`MATCH_CONFIDENCE_THRESHOLD`, `AMBIGUOUS_MARGIN`,
  `PRESENCE_ON/OFF_RATIO`) และวิธีสร้าง embedding ไม่เปลี่ยน — สินค้าเดิมใช้ได้ทันที

## ตรวจสอบซ้ำ

จากโฟลเดอร์ `backend`:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

จากโฟลเดอร์โปรเจกต์:

```powershell
node frontend/tests/kiosk.test.cjs
node frontend/tests/products.test.cjs
node --check frontend/static/js/calibrate.js
```

การทดสอบครอบคลุมภาพจำลองที่แสงเปลี่ยน วัตถุอยู่นิ่ง มือผ่านสั้น ๆ ภาพเบลอ
ภาพกล้องเก่า การยกของออกระหว่าง inference คะแนนหลอกจากภาพเดียว
การเลือกด้วยมือ การบันทึกข้อมูลล้มเหลว และการอัปเดตหน้าเว็บ
ใช้ฐานข้อมูลชั่วคราวสำหรับการเขียนทดสอบ ไม่ล้างหรือแทนข้อมูลสินค้าจริง

ผลทดสอบเหล่านี้ไม่ใช่การวัดเปอร์เซ็นต์ความแม่นยำกับสินค้าในสถานที่จริง
ยังต้องทดสอบด้วยสินค้าจริงและของที่ไม่ได้ลงทะเบียนภายใต้แสงใช้งานจริง
ระบบไม่ได้มีโมเดลแยกมือโดยเฉพาะ มือที่ค้างนิ่งหรือสินค้ารูปร่างคล้ายกันมาก
ยังอาจทำให้ผลคลาดเคลื่อนได้ การหมุนเร็วหรือแสงน้อยมากอาจถูกปฏิเสธเพราะภาพไม่ชัด
กล้องที่ย้ายตำแหน่ง เปลี่ยนความละเอียด หรือเปลี่ยนหมายเลข USB ต้องตรวจพื้นอ้างอิงใหม่
